## 按任务定义“社交”

存在行人不等于符合社交规范。静态导航关注可达性，动态避障关注随时间变化的障碍；社交导航还需操作性地定义让行、群体空间、通行秩序或不适。提前停住可以安全却长期冻结，穿过交谈群体可以无碰撞却违反任务规则。

## 十二模块的参考架构

以下为工程设计建议，不是上游已有的十二个同名组件。训练与系统评测可用不同运行器，但共享情景、动作与指标契约；同一实例只有一个物理状态所有者。

| 模块 | 对外交付 |
|---|---|
| 资产与版本 | 可追溯几何、单位和来源 |
| 地图与语义区域 | 占据图、NavMesh、社会区域 |
| 情景生成 | 起终点、种子、事件清单 |
| 行为与群体 | 目标、期望速度、反应规则 |
| 人体运动 | 根位姿、身体姿态、碰撞包络 |
| 机器人控制 | 有单位和有效期的动作 |
| 传感与观测 | 时间戳、内外参、合法可见信息 |
| 环境与训练 | transition、终止与 reset |
| 算法与 ROS 2 适配 | 统一策略/服务接口 |
| 独立评测 | 可离线重算的指标 |
| 调度与回放 | 版本清单和完整事件流 |
| 验证与发布 | 固定测试集、统计与失败分布 |

## 指标必须有分母与定义

同时记录成功、碰撞、超时、到达时间、路径长度、冻结时长、最近人机距离和动作平滑性。群体侵入时间、通行侧违反次数等需定义区域和事件；距离阈值不能直接代表真实人的舒适感。

SPL 的参考最短路径需说明是在静态地图上计算，还是考虑动态时间约束。策略失败的 episode 也进入总分母。训练种子间变化与同一策略评估回合间变化分别统计。

## 官方资料补充与验收

InteractiveScene 提供场景复制与实体组织的参考；ROS 2 QoS 文档说明接口连通还依赖兼容的传输策略；ProtoMotions 支持物理人体，但不自动提供社交规则。固定对向、交叉、门口瓶颈、超越、群体和遮挡情景，分别记录人群密度、反应性和机器人尺寸。

评估器可读取真值不代表策略可以读取真值。训练/测试按实际泛化目标拆分场景，保存全量 episode、失败原因与可重算指标。动画回放、规则避让和学习反应型人群是不同实验条件。后续见 [人群运动接口](../crowd-motion/) 和 [配对评测](../paired-evaluation/)。
